# IB-03R — Distributed issuer replay and rotation consistency
LAB scope: isolated PostgreSQL 16. A central shared nonce table (unique kid+nonce), an authoritative key epoch and explicit retirement state are used across separate PostgreSQL clients representing issuer replicas. Key state is locked FOR SHARE while claiming a request, serializing revocation with successful claims. The test checks forged request nonce, exactly one winner among eight clients, old epoch denial and read-only replica role.

**Critical limitation:** the test's 8 spawned PostgreSQL clients are independent connections, not real deployed issuer replicas. The standalone claim function does not authenticate an Ed25519 signature inside SQL; it MUST only be called from a verifier after signature validation, and compromised role access can preempt or burn nonce. The current IB-03Q gateway has not been swapped over to this DB-backed claim and still uses local O_EXCL files. Epoch check in the sample verifier is static 1. Cluster partitions, replica lag, mTLS, shared revocation propagation, issuance race with database network failures, key distribution and signing custody remain unverified. The key table is writable by test DB owner; compromised owner is out of scope. No live writes, Supabase migration, merge or deployment.

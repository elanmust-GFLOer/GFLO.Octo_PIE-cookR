# GFLO IB-03Q — Issuer Authentication, Rotation & Compromise Containment

**CI LAB ONLY / PRODUCTION BLOCK.** Admission requests use independently generated Ed25519 keys stored under the separate admission Unix UID. The issuer runs under the issuer UID, checks a pinned public-key allowlist, short-lived domain-separated request authorization, and consumes a request nonce with an atomic O_EXCL file creation before independently verifying the original EOA SIWE signature and immutable PostgreSQL challenge. A separate issuer HMAC key and read-only PostgreSQL role remain from IB-03P. Rotating admission signing keys invalidates previous key IDs. A compromised admission signer cannot bypass independent SIWE/context verification without the wallet signature.

**Limitations:** This is process-invoked IPC via stdin, not a live TLS/mTLS issuer network service. Both OS identities share the GitHub runner root; no KMS/HSM, remote attestation, secure monotonic clock, distributed replay ledger or production RBAC. Root stages the ephemeral admission keys and issuer trust store, so a compromised root can bypass the boundary. Request replay ledger is local filesystem only; not shared across hosts. Verifier-to-session proof and key custody remain root-of-trust limitations. This tests **admission request key rotation**, not a complete HMAC issuer-secret rotation and migration. Issuer corruption, side channels, full EIP-4361 conformance, ERC-1271 and distributed response-disclosure fencing are production blockers. No live deployment, Supabase migration, Lovable change, merge or wallet action.

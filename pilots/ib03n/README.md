# GFLO IB-03N — Immutable Challenge Context & Issuer Isolation
**LAB CANDIDATE / PRODUCTION BLOCK.**

Adds a separate, challenge-keyed PostgreSQL 16 context row whose URI, domain, subject, wallet, chain, scope, full message digest, binding and consent generation, issued and expiry timestamps are persisted once. A row trigger rejects UPDATE and DELETE. A reader-only, SECURITY DEFINER facade compares context fields with the nonce table, and the verifier uses these database facts rather than synthetic fallback fields. The attestation issuer test role has no challenge DB read/write permission. Real EIP-191 EOA signature recovery precedes an ephemeral HMAC signer and D3 nonce-consuming PG session issuance.

**Limitations:** owner/DDL privileges can disable triggers or change context. The signer in CI still shares a test process with admission; issuer process/network/key custody isolation is **NOT PROVEN**, though its independent DB role is denied access. The signer key is available in test process memory and test DB owner. Challenge issuance via a privileged SQL fixture is NOT hardened service issuance; session ID supplied by the laboratory caller. Further, the old IB03L admission function does not independently re-read ib03n context inside its atomic transaction, so concurrent challenge-context/consent transitions beyond its D3 protections remain a production boundary gap. Real SIWE host-origin enforcement, complete EIP-4361 parser, ERC-1271, KMS/HSM and production RBAC/RLS remain unverified. No production merge or deployment authorized.
